- (decision) Consumer is a single data analyst building a dashboard; primary metric is member activity by segment
- (decision) DP_Member_360 is the final product, delivered via client's Unity Catalog; analyst queries one table, no joins required
- (decision) Daily batch refresh from 8 microservice source extracts; no near-real-time requirement
- (decision) Widen DP_Member_360 with activity measures - current 10-column profile-only schema cannot answer the headline metric at all
- (decision) Grain is one row per member (wide table) with 30-day and lifetime windows; rejected daily-snapshot grain as over-engineering for a demo, and the column-add path is reversible
- (decision) Activity measures count Posted transactions only; Pending excluded so a mutating row cannot be double-counted across daily runs
- (decision) Carry channel_group and transaction_category through from dimension tables - free to include, unlocks digital-vs-assisted cuts without a 3-table join
- (decision) Scope ceiling: analyst must answer 'activity by segment' plus the one follow-up 'which members went quiet' - nothing beyond that in v1
- (event) Data finding: source Member.csv has 10 rows with IDs M0001, product DP_Member_360 has 100 rows with IDs M000001 - sample product was not generated from sample raw files; ID format needs a documented contract
- (event) Data finding: product schema already drops first_name/last_name/postal_code and substitutes age_band/home_state - de-identification appears deliberate, treat as a governance requirement
- (decision) Brad chose: name 'Member 360 Data Product', internal-tool depth (~5 pages), Fast path drafting; learning exercise so perfection is not the bar
- (event) Fast-path draft written: prd.md (12 sections, 13 FRs, 4 SMs + 2 counter-metrics, 6 open questions) and addendum.md (schema, grain options, pipeline shape)
- (event) GAP FOUND POST-DECISION: wide-table grain has no history, so week-over-week trend is not computable - this partially undercuts the headline metric and reopens the grain argument. Raised as Open Question 3, not silently papered over
- (assumption) Databricks/Delta inferred from 'Unity Catalog'; GLBA assumed as applicable regime for a credit union; USD-only; activity thresholds 30/90 days are placeholders pending verification
- (change) Research-driven: activity measures now count MEMBER-INITIATED transactions only - excludes Interest/Fee categories and System channel (TT09,TT10,C09,C10). Reason: interest postings are not member engagement, and 'member-initiated' is the distinction that carries weight in unclaimed-property law
- (change) Renamed activity_status value Dormant -> Inactive. Reason: dormancy is a regulated state under state unclaimed-property law (3-5yr clock, UPA); using the word for a 90-day analytical cut puts a legal term on a dashboard meaning something else
- (change) Governance reworded from 'de-identified' to 'pseudonymized' - GLBA has no de-identification safe harbor and member_id remains a re-identification key; named NCUA Reg P + Part 748 as the implementing rules, HIPAA Safe Harbor as design yardstick only
- (change) FR-12 restructured onto DAMA six DQ dimensions (added timeliness + accuracy-via-reconciliation); FR-10 added catalog certification requirement and flagged that DP_Member_360 departs from UC lowercase snake_case convention
- (event) Open Questions grew 6 -> 8: added OQ7 (is C10 API member-initiated or system?) and OQ8 (does client already publish a competing 'active member' definition?)
- (decision) RESOLVED OQ3 (trend gap): chose prior-period columns (txn_count_prior_30d, txn_amount_prior_30d) over a history table. Reason: simplest option that still answers the headline - no new table, no grain change, no snapshot double-count risk, reuses existing aggregation with a shifted date predicate. Accepted limit: one comparison, not a time series
- (decision) Deliberately NO txn_count_change_pct column - analyst holds both counts, BI layer divides. A stored ratio is a third value that can disagree with its own inputs
- (change) SM-C1 column budget raised 24 -> 26, once and explicitly, to admit the prior-window measures. Noted in the metric itself that this is the only legitimate way the budget moves
- (change) UJ-2 rewritten around the went-quiet filter (txn_count_prior_30d > 0 AND txn_count_30d = 0) - better retention list than 'currently inactive' because it excludes members who were never active
